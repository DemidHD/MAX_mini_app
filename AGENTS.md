## Что это за продукт

MAX Найм — Mini App внутри MAX: владелец микробизнеса (1–10 сотрудников, HoReCa, Москва) проходит путь от кадровой потребности до назначенного собеседования с минимумом ручных действий. Конечный результат обязательного маршрута — `Interview scheduled`.

## Ключевые инварианты (нарушать нельзя)

- `users.user_id` = идентификатор пользователя MAX = PRIMARY KEY. Отдельного внутреннего `users.id` нет.
- Личность пользователя определяется только серверной сессией. `user_id` / `candidate_id` / `employer_id` из тела запроса не являются источником истины.
- `initData` проверяется на сервере (HMAC-SHA256). `initDataUnsafe` не доверенный источник. `MAX_BOT_TOKEN` и `MAX_WEBHOOK_SECRET` — разные секреты, только на backend.
- Новый пользователь: `role = NULL`. Авторизация роль не назначает.
- Бизнес-статусы меняет только backend. Frontend их не выставляет.
- P0 не зависит от AI. AI — P1 и выше, с обязательным ручным fallback.
- Порядок реализации строго сверху вниз по приоритету: P0 → P1 → P2 → P3. Функцию низкого приоритета не начинаем, пока не стабилен верхний слой.
- Matching и автоматические решения не используют фото, пол, возраст (вне требований закона) и субъективные характеристики.
- Ошибка уведомления в MAX не откатывает созданное интервью.
- Бронирование слота атомарно; занятый слот → `409 Conflict`.

## Стек (зафиксирован)

Backend: Python 3.10+, FastAPI, Pydantic v2, Tortoise ORM, `maxapi[fastapi]` (webhook в production), Uvicorn, PostgreSQL.
Frontend: React, TypeScript, MAX UI, MAX Bridge.
Инфраструктура: Docker, Docker Compose, HTTPS, env vars, локальное файловое хранилище `storage/` в persistent volume.
