# AI Gateway

Единственная точка вызова LLM во всей системе (тех. ТЗ 1.2, 5). Домены Core API
никогда не обращаются к YandexGPT или GigaChat напрямую — только к этому
сервису по внутреннему адресу.

Наружу не публикуется: порт доступен только внутри docker-сети, эндпоинты живут
под префиксом `/internal`. Поэтому в сервисе нет CORS — браузер сюда не ходит.

```
src/navigator_ai/
  config.py        настройки: провайдер, ключи, таймауты, TTL кэша
  logging.py       логи; сервис независим и не тянет пакет navigator
  cache.py         клиент Redis для кэша идентичных запросов
  costs.py         журнал стоимости запросов (тех. ТЗ 5, п. 5)
  deps.py          зависимости FastAPI: настройки и активный провайдер
  prompts.py       шаблоны промптов на Jinja2
  providers/       интерфейс, заглушка, YandexGPT, GigaChat, кэш, повтор
  templates/       сами шаблоны: правка формулировки не требует передеплоя
  main.py          сборка приложения, пробы, три внутренних эндпоинта
```

## Как собран активный провайдер

    CachedProvider( ResilientProvider( основной, резервный ) )

Кэш снаружи намеренно: попадание в него должно снимать и повтор, и фолбэк —
иначе кэш не экономит ничего в единственном случае, ради которого заведён,
когда модель тормозит.

Резерв подключается, только если задан `GIGACHAT_API_KEY`. Без него шлюз честно
отдаёт отказ основного провайдера. Заглушка резервом не бывает никогда:
подменять недоступную модель выдумкой хуже, чем отказать.

## Запуск

```bash
uv sync
uv run uvicorn navigator_ai.main:create_app --factory --reload --port 8100
uv run pytest
```

Без uv, из этого каталога (`requirements.txt` производный от `uv.lock`,
генерируется `make requirements`, решение Р75):

```bash
python3.13 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn navigator_ai.main:create_app --factory --host 127.0.0.1 --port 8100
```

## Состояние

Сделано всё, что перечислено в тех. ТЗ 5: три внутренних эндпоинта, шаблоны
промптов на Jinja2, повтор и фолбэк, кэш в Redis, учёт расхода и стоимости.

**Не сверено с живыми API.** Клиенты YandexGPT и GigaChat написаны по
публичным описаниям: ключей в проекте нет, а домены провайдеров закрыты
сетевой политикой окружения разработки — тем же прокси, что и `dev.max.ru`
(тех. ТЗ 9.7). Всё, что зависит от документации, собрано в `_payload` и
`_read` каждого клиента: сверка изменит их тела, а не структуру кода.

**Снимать `LLM_PROVIDER=mock` до сверки нельзя.** Непроверенный клиент даст
либо постоянный отказ, либо, что хуже, тихо неверный разбор ответа — а на
разборе ответа держится модерация вопросов в блоке 5.

Цены токенов в `costs.py` взяты из публичных прайс-листов и тоже не проверены:
ошибка в них искажает отчёт о расходах, но не работу шлюза.

## Открытый вопрос: где хранить журнал стоимости

Тех. ТЗ 5, п. 5 требует логировать стоимость каждого запроса «в отдельную
таблицу». Таблица означает базу, а на схеме сервисов (тех. ТЗ 1.4) у AI Gateway
доступа к PostgreSQL нет. Варианты:

1. Дать шлюзу отдельную схему в том же PostgreSQL — быстро, но появляется вторая
   точка доступа к базе.
2. Писать расход в структурированный лог, а агрегировать снаружи — не требует
   базы, но история живёт только в логах.
3. Возвращать расход в ответе (уже возвращается — поле `total_tokens`) и писать
   его в базу на стороне Core API — база остаётся у одного сервиса, но учёт
   размазывается по вызывающим доменам.

Решение принимается вместе с первым настоящим провайдером. До тех пор расход
считается и возвращается в ответе, но никуда не пишется.

## Заглушка провайдера

`LLM_PROVIDER=mock` отвечает мгновенно, без сети и одинаково на одинаковый
промпт. Тех. ТЗ 7 требует, чтобы система никогда не тестировалась настоящими
вызовами LLM: это нестабильно, дорого и недетерминированно. В
`ENVIRONMENT=production` заглушка запрещена — сервис с ней не поднимется, иначе
модерация вопросов в блоке 5 работала бы вслепую.
