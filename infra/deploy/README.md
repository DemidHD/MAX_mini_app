# Выкладка на стенд

Сервер сам проверяет реестр и обновляется. Снаружи в него никто не стучится.

## Почему так, а не по SSH

Входящий SSH с раннеров GitHub до этого сервера не доходит. Проверено пробой
`Диагностика SSH` на четырёх сочетаниях: порты 22 и 2222, полный и урезанный
набор алгоритмов. Везде одинаково — TCP устанавливается, баннер сервера
приходит, а на первом же пакете обмена ключами наступает тишина до таймаута.

Это исключает и фильтр по номеру порта, и потерю крупных пакетов: урезанный
набор ужимает `KEXINIT` примерно до трёхсот байт, и он не проходит так же.
Направление «сервер наружу» при этом рабочее. Подробнее — решение Р71
в [`DECISIONS.md`](../../DECISIONS.md).

## Как это работает

1. CI собирает образы и кладёт их в GHCR с тегом коммита и `latest`.
   В образ проставляется метка `org.opencontainers.image.revision`.
   Образов три: core, miniapp и ai-gateway. Точка входа — официальный
   `nginx:1-alpine`, своей сборки ей не нужно (решение Р76).
2. Таймер systemd раз в минуту запускает `update.sh` на сервере.
3. Скрипт забирает манифест `core:latest` и читает из метки коммит.
   Если коммит тот же и все сервисы живы — выходит, ничего не делая.
4. Иначе скачивает `docker-compose.yml` и конфигурацию nginx **того же
   коммита**, поднимает стек с `IMAGE_TAG` равным этому коммиту и проверяет
   `/health` изнутри сервера.

Файл compose один и тот же локально и на стенде: `build` и `image` уживаются
в одном определении, а всё различие между окружениями сведено к `.env`.
Скрипт выкладки поднимает стек с `--no-build`, чтобы сервер ни при каких
обстоятельствах не начал собирать образы сам (решение Р70).

Проверка живости делается на сервере, а не в workflow, по той же причине,
по которой выкладка перевёрнута: раннер до стенда не достучится.

## Сертификат

Автоматического выпуска больше нет: nginx берёт готовую пару из переменных
окружения (решение Р76). Откуда взялся сертификат — его дело не касается,
лишь бы это был PEM.

```bash
cd /opt/navigator
echo "TLS_CERT=$(base64 -w0 fullchain.pem)" >> .env   # сертификат с цепочкой
echo "TLS_KEY=$(base64 -w0 privkey.pem)"    >> .env   # закрытый ключ
chmod 600 .env
```

base64 — ради того, чтобы значение было однострочным: многострочный PEM
прямо в `.env` живёт плохо. Сам nginx принимает и обычный PEM, так что
передать его можно и напрямую окружением:

```bash
TLS_CERT="$(cat fullchain.pem)" TLS_KEY="$(cat privkey.pem)" docker compose up -d nginx
```

но для постоянной конфигурации стенда однострочный base64 в `.env` надёжнее.

Обе переменные задаются вместе. С одной из двух контейнер не поднимется —
это почти всегда опечатка в имени, и молча свалиться в самоподписанный
сертификат тут нельзя: снаружи такой стенд неотличим от рабочего, а внутри
сломан. Соответствие ключа сертификату проверяет сам nginx.

**Продление ручное.** Это цена отказа от автовыпуска, и забыть про неё
означает уронить стенд молча: мини-приложение MAX работает во WebView и без
HTTPS не запускается вовсе. Срок годности:

```bash
# openssl внутри контейнера нет (см. Р76), поэтому PEM читается снаружи.
docker compose exec -T nginx cat /etc/nginx/certs/cert.pem | openssl x509 -noout -enddate
```

Обновление — переписать `TLS_CERT` и `TLS_KEY` в `.env` и выполнить
`docker compose up -d nginx`: изменение окружения compose видит сам и
пересоздаёт контейнер.

Домен должен указывать на этот сервер A-записью. Проксирование через
Cloudflare (оранжевое облако) — отдельное решение с другими последствиями;
если сертификат выпущен как Cloudflare Origin Certificate, оно обязательно,
потому что такой сертификат доверенный только за их проксёй.

## Переменные стенда

Всё это лежит в `/opt/navigator/.env`. Выкладка этот файл не трогает.

| Переменная | Что это | Без неё |
|---|---|---|
| `DOMAIN` | домен стенда | проверка живости в журнале ничего не скажет |
| `TLS_CERT`, `TLS_KEY` | сертификат с цепочкой и ключ, PEM или base64 | nginx поднимется с самоподписанным и напишет об этом в лог |
| `HTTP_PORT`, `HTTPS_PORT` | порты наружу, на стенде `80` и `443` | умолчания и так `80`/`443` |
| `ENVIRONMENT=staging`, `DEBUG=false` | режим стенда | останется локальный режим с DEBUG |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | доступ к базе | подставится умолчание `navigator`/`navigator` — и на уже живом стенде всё встанет с ошибкой авторизации, потому что том создан под настоящий пароль |
| `ADMIN_PASSWORD` | пароль админки | не поднимется `admin`: без пароля админка отказывается стартовать сама |

Остальные переменные из `.env.example` имеют разумные значения по умолчанию
прямо в `docker-compose.yml` и задаются только при необходимости. Умолчания
рассчитаны на локальный запуск, поэтому `.env` на стенде — это ровно список
отличий от него.

**Отсюда следует важное.** Строгих `${VAR:?}`, которые раньше не давали
подняться без переменной, в общем файле не осталось — иначе локальный запуск
без `.env` был бы невозможен (решение Р77). Забытая строка в `.env` стенда
теперь не останавливает подъём, а тихо оставляет локальное умолчание. Колонка
«Без неё» выше поэтому описывает не «не поднимется», а что именно произойдёт.

## Установка

Один раз, под root. Дальше всё само.

```bash
# 1. Каталог и конфигурация стенда должны уже существовать:
#    /opt/navigator/.env — переменные из таблицы выше.

# 2. Скрипт обновления
curl -fsSL https://raw.githubusercontent.com/Danil-prog-coder/MAX_mini_app/main/infra/deploy/update.sh \
  -o /opt/navigator/update.sh
chmod +x /opt/navigator/update.sh

# 3. Юниты systemd
curl -fsSL https://raw.githubusercontent.com/Danil-prog-coder/MAX_mini_app/main/infra/deploy/navigator-update.service \
  -o /etc/systemd/system/navigator-update.service
curl -fsSL https://raw.githubusercontent.com/Danil-prog-coder/MAX_mini_app/main/infra/deploy/navigator-update.timer \
  -o /etc/systemd/system/navigator-update.timer

systemctl daemon-reload
systemctl enable --now navigator-update.timer
```

## Проверить

```bash
systemctl start navigator-update      # выложить прямо сейчас, не дожидаясь таймера
journalctl -u navigator-update -f     # что происходит
systemctl list-timers navigator-update
cat /opt/navigator/.deployed          # какой коммит выложен
```

## Откат

Тег образа — SHA коммита, поэтому откат это запуск с прежним значением:

```bash
cd /opt/navigator
export IMAGE_TAG=<коммит, на который откатываемся>
docker compose up -d
```

Таймер вернёт стенд к последней сборке при следующей проверке, поэтому на
время разбирательства его стоит остановить: `systemctl stop navigator-update.timer`.

## Обновление самого скрипта

`update.sh` лежит на сервере и сам себя не обновляет — намеренно: скрипт,
переписывающий себя во время работы, чинится тяжело. Если он изменился
в репозитории, повторите шаг 2 установки.
